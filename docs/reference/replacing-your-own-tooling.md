# Replacing your own tooling with this setup

A machine often arrives with its own scripts for cloning repositories, managing worktrees,
installing agent skills and assembling agent context. This page maps each of those jobs to what this
base provides, so a migration plan can retire the old tool one job at a time. Do one job, prove it,
then the next; the old tool keeps working for the jobs not yet moved.

| Job | Here | Configure | Reference |
| --- | --- | --- | --- |
| Which repositories a machine has | `mani` with the domain's `~/Devel/mani.yaml` | the private layer's `Devel/mani.yaml.tmpl` | [`fleet-manifest.md`](fleet-manifest.md) |
| Cloning them (`mani sync`), in the chosen shape | `fleet-repo clone <name>` as a project's `clone:` | `clone:` and `container:` per project (`worktrunk.layout` only to override) | [`repository-layouts.md`](repository-layouts.md) |
| Running one command across them | `mani run <task>`, `mani exec` | `tasks:` in the manifest | `mani --help` |
| Creating, entering, landing, removing worktrees | `wt` (worktrunk), with config generated by `wt-config-gen` | `~/.dotlocal/worktrunk.toml`, `worktrunk:` per project | skill `working-in-worktrees` |
| Installing dependencies in a new worktree | `wt-bootstrap` (worktrunk's pre-start hook) | `worktrunk.bootstrap: true` | skill `working-in-worktrees` |
| Agent skills: generic ones | the base's own skills, deployed to `~/.claude/skills` | `skipSkills` to leave one out | [`private-layer.md`](private-layer.md) |
| Agent skills: from the domain's own repositories | `skill-externals-sync` | `~/.dotlocal/skill-externals.yaml` | [`private-layer.md`](private-layer.md#skills-from-other-repositories) |
| Agent skills: a domain's specifics for a base skill | a fragment the skill reads | `~/.dotlocal/skills/<skill>.md` | [`private-layer.md`](private-layer.md) |
| Global agent instructions | `~/.claude/CLAUDE.md`: the base's standards, then the domain's | `~/.dotlocal/claude/CLAUDE.md` | [`private-layer.md`](private-layer.md) |
| Standing rules every session loads | the knowledge base's Tier-0 projection, imported by the domain's `CLAUDE.md` | a KB in the notes repository | [`knowledge-base.md`](knowledge-base.md) |
| Claude Code settings | the base's merge into `~/.claude/settings.json` | `~/.dotlocal/claude/settings-declared` | [`private-layer.md`](private-layer.md) |
| A repository's own agent context | its `AGENTS.md` (with `CLAUDE.md` importing it) | per repository; checked by `context-lint` | skill `project-context-file` |
| Notes, decisions, plans, a work register | a notes repository in the standard `docs/` layout, with `register`, `adr-lint`, `doc-lint`, `register-lint` | per repository | skills `project-documentation` (including its section on adopting the layout in an existing notes repository) and `register-standard` |
| Keeping program ids and private terms out of code repositories | `leak-guard`, on every commit and push | `~/.dotlocal/git-leak-*`, `leakPolicy` per project | [`private-layer.md`](private-layer.md#the-publish-guard), [`fleet-manifest.md`](fleet-manifest.md) |

## A migration order that keeps the machine working

1. **Bring the dotfiles current** and write the private layer: identity, the shell fragments, the
   Claude Code instructions and settings ([`private-layer.md`](private-layer.md)). Check with
   `setup/overlay-doctor` and `setup/overlay-doctor --machine`.
2. **Write the manifest** for the repositories already on disk, pointing `path:` at where they are
   today, and validate it with `fleet-decl --check`. Nothing is moved yet; `mani` now knows them.
3. **Convert repositories to the chosen layout** one at a time
   ([`repository-layouts.md`](repository-layouts.md)), then let `mani sync` own cloning.
4. **Move worktree handling to `wt`**, repository by repository, once its layout is declared.
5. **Move skills:** the old tool's skills either become base skills (generic), entries in
   `~/.dotlocal/skill-externals.yaml` (from a repository), or fragments of a base skill (a domain's
   specifics).
6. **Move context:** global rules into `~/.dotlocal/claude/CLAUDE.md` or a KB, each repository's own
   into its `AGENTS.md`.
7. **Move notes** into a notes repository in the standard layout, following the adoption section of
   skill `project-documentation`; declare it `leakPolicy: notes` in the manifest.
8. **Retire the old tool** once nothing calls it: search shell history, scripts and aliases for its
   name before deleting it.
